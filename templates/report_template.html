三、口径与判定规则

列数据来源口径与判定规则
ASIN 监控清单（config.json 的 asinList） 行序固定为清单顺序，不随数据源返回顺序变化。当前监控 {{ASIN_COUNT}} 个。新增 / 移除只改 config.json，不动代码。
产品 运营命名（config.json） 中文简称由运营定稿，用于内部识别；与平台原标题不同（原标题过长，不适合进表格）。
可售状态 卖家精灵 getAsinDetail 接口有正常返回 → 可售；接口无数据 → 不可售（此时价格、评分等显示为 -）。
Buy Box 卖家精灵 sellerId + fulfillment 卖家 ID 属于品牌方（{{BRAND_SELLER_IDS}}）且配送方式为 FBA → 是；否则红字「异常」。
异常分两种：① 平台自营抢走（卖家显示 Amazon、配送 AMZ）——需运营干预；② 纯数据缺失（卖家字段为空）——通常为抓取漏项。
价格 ({{CURRENCY}}) 卖家精灵 getAsinDetail.price 为到手价（含促销后的实际售价），不是 ERP 标价。与上一交易日基线比较，不一致 → 红字「异常」。
注：ERP 的商品标价普遍高于到手价，两者口径不同，不可混用（混用会让整列误报）。
Coupon 卖家精灵 coupon，为空时由积加 ERP 广告券报表兜底 今日有券 → 紫色徽章显示券值（金额 $2 coupon / 百分比 5% coupon）；
今日无券、昨日有券 → 红色「coupon 消失」；两日均无 → 灰字「无」。
取值优先级：卖家精灵有值以它为准 → 为空时用 ERP 在跑的券补填 → 两者都无才判「无」。该字段在卖家精灵侧会成批漏抓，直接采信会造成「券消失」误报。
Prime 专享 {{PRIME_SOURCE}}，卖家精灵 primePrice 作兜底 当前有 Prime 专享折扣 → 紫字 Prime$29.99（显示折扣价）；未做折扣 → 单元格留空。
该字段在卖家精灵侧同样会成批漏抓（同批数据几分钟内从有值变全 -1），因此以实时抓取为准。
Rating 卖家精灵 getAsinDetail.ratings 该 ASIN 的累计评论数，绿色徽章 +N 为与上一交易日的增量。变体家族共享评论池，同父体商品的 Rating 数值会一致。
Review 卖家精灵 getAsinDetail.rating 亚马逊星级评分（0–5，如 ★4.6），不是评论数。
大类排名 卖家精灵 bsrRank 一级类目畅销排名（{{GROSS_LABEL}}）。数字越小越好。
与上次监控相比波动 ≥ {{THRESHOLD_GROSS}} 名 → 红字「异常」。
小类排名 卖家精灵 subcategories[0].rank 末级细分类目畅销排名（{{SUB_LABEL}}）。
与上次监控相比波动 ≥ {{THRESHOLD_SUB}} 名 → 红字「异常」。
个别 ASIN 挂多个小类，固定取第一个（主类目）；类目名与基线不一致时自动不环比并告警（平台调整类目时数字不可比）。
FBA 库存预警 积加 ERP post_purchase_store_fbaInventory_page_V2 可售天数 = 平台仓可用量 ÷ 30 天日均销量，仓库口径 {{WAREHOUSE}}。
< {{THRESHOLD_FBA}} 天 → 红字「异常 · N天」；≥ {{THRESHOLD_FBA}} 天 → 绿字「正常 · N天」；无数据 → 「—」。
同一 ASIN 存在多条 MSKU 时，取有库存的那条（可用量最大者）。不用商品列表的「可履约数量」——口径更小会低估。
